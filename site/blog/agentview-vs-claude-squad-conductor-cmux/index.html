How to run multiple Claude Code agents at once

13 November 2026

Ten tools for running more than two coding agents, what each one is built for, and when to pick it over the others.

I build agentview, so read this with that in mind. I checked every claim below against the tool's own repo, docs or pricing page on 13 November 2026. Where I could not confirm something, the table says so.

What you need at ten agents

Three problems show up once you run more than two agents.

  1. You do not know which agent is waiting for you.
  2. Agents edit the same files and step on each other.
  3. Several agents start a build at once and the machine grinds to a halt.

Each tool below solves a different slice. Some give every task its own git worktree. Some only show you a list. Some are whole apps with their own agent inside. Almost none address the third problem.

Where each one is the better pick

Claude Code's agent view

If Claude Code is the only agent you use, start here. It is built in, so there is nothing to install. Each session you dispatch from claude agents moves into its own git worktree before it edits files, and you can peek, reply and attach from one screen. Anthropic still calls it a research preview. The docs say it runs Claude sessions only, and that ten agents in parallel use your quota about ten times as fast as one. See the agent view docs.

claude-squad

Pick it if you want a terminal tool that gives each task its own worktree and works with several CLI agents. It is open source and free. It needs tmux and gh, and the last release (v1.0.20) came out in August, though the repo had a commit on the day I checked. See the repo.

Conductor

Pick it if you are on a Mac and want a polished app that handles the whole loop: a workspace per task, diff review, pull request, merge. Two cautions. It is closed source and Mac only. Its future is also unclear. On 4 November the team announced it was joining Meta and that Conductor Cloud would shut down. The announcement page now strikes through the shutdown paragraph and says, "We'll still be developing Conductor." See the announcement.

cmux

Pick it if you live in a terminal and want it to be fast and native on a Mac. It is a Ghostty-based terminal with vertical tabs, a ring around the pane that needs you, and a scriptable browser. It runs any CLI agent. It is not a worktree manager, and its own README calls it "a primitive, not a solution". See the repo.

Paradev, formerly Superset

Pick it for worktree-per-task feature work with review built in: a Changes pane, pull requests with checks, and a browser preview per workspace. It also has automations, remote hosts and an iPhone app. The Superset repo was renamed Paradev in late October, and the CLI is still called superset. See the README.

OpenCode's own TUI and web UI

If you already use OpenCode, you may not need another tool. All its clients attach to one shared server. The TUI has session tabs, a jump to the next unread tab, and parent and child sessions for subagents. A pairing link opens the web UI on your phone. It only manages OpenCode sessions. See the TUI docs.

Cursor and the Codex app

Pick these if most of your work already happens in them. Both run their own agent. Cursor's cloud agents run in isolated VMs, so you can start many without loading your machine. Both now have voice that hands work to the agent. ChatGPT Voice in the Codex app can start tasks, check progress and steer them, and Cursor's voice chat does the same inside a chat. See Cursor voice chat and ChatGPT Voice.

tmux and git worktrees

Pick this for full control and any agent. git worktree gives each agent its own checkout, and tmux or Zellij holds the sessions. Nothing here knows what an agent is, so you write your own status and notifications. Worktrunk is a small CLI that adds worktree commands built for agents. Claude Code also has claude --worktree, which creates one for you (docs).

agentview

Pick it if you use more than one harness and want one list. It reads the sessions your harnesses already keep, so you do not change how you work. Rows are grouped by what needs you, and Enter opens the harness's own screen. Two features go beyond the list. Ctrl+K starts a voice call across your sessions, and it shows the agent-bouncer queue above the input, so you can see which sessions are stuck behind a full machine.

The header also shows rate-limit windows and reset times for Claude and Codex. If you keep a second Claude subscription in a ~/.claude-* profile, it gets its own row next to the first. On macOS, agentview reads those logins from the Keychain.

Where it is weaker:

  • It does not create worktrees, review diffs or open pull requests. Pair it with one of the tools above for that.
  • Voice works with OpenCode sessions only.
  • Replying and approving from the list depends on the harness. For Claude Code rows, you still reply in Claude's own screen. The README has the full table.
  • Rows are not labelled by Claude account. Claude sessions come from the one config directory agentview runs under, so a second account shows up in the usage header only.
  • It is terminal only.

Voice is no longer rare

Codex and Cursor both have a voice call that hands work to their own agents. Claude Code and Conductor have dictation. agentview's call is different in one way: it spans sessions from your whole list, searches your history, and starts sessions in other folders. It is also narrower: it only reaches OpenCode sessions today.

Resource control is almost empty

cmux and Paradev show CPU and memory per workspace. Three tools go further. Claude Code's agent view stops idle sessions when memory is low. The Codex app caps how many spawned-agent threads one session can open. Xum (formerly Mux, by Coder) sets a CPU and memory limit for all local agent commands, but only on Linux, through cgroup v2 (docs).

As far as their docs say, none of these holds a heavy job in line until the machine has room for it. That is what agent-bouncer does, on macOS and Linux. The second post explains how.

Names and status that changed

  • Crystal was deprecated in February 2026 and replaced by Nimbalyst, an MIT-licensed desktop app for Claude Code and Codex, with OpenCode and Copilot in alpha.
  • Superset became Paradev in late October 2026.
  • Mux became Xum after a trademark concern.
  • Vibe Kanban's company shut down in April 2026. The repo is Apache-2.0, is not archived, and had a commit on 12 November, but the last tagged release was in April. See the shutdown post.
  • Emdash (Apache-2.0, worktree per task, 35 agent CLIs by its docs) says new development has moved to a cloud-first 2.0.

What I could not confirm

  • Conductor's current pricing, since its pricing page redirects to the home page.
  • Whether Cursor's agents are open source. The docs I read do not say.
  • Platforms for OpenCode, and voice or resource features for tools where I found none. "None found" means I searched the docs, not that the feature cannot exist.
  • Prices change often. Check each pricing page before you buy.
